# webcopytest — Triptych Interactive homepage (local copy)

A saved copy of the [Triptych Interactive](https://www.triptych.co) homepage, repaired so it runs on your computer.

> **Good to know:** this is not a plain HTML/Bootstrap site. It is the production build of a
> **Next.js (React)** app, styled with **Tailwind CSS**, with a **Three.js** 3D hero.
> All the `<link>`/`<script>` tags were generated by Next.js — nothing has to be linked by hand.

## Run it

Double-clicking `index.html` **will not work** (see [why](#why-it-would-not-launch)). Use any one of these:

| Option | What to do | Then open |
| --- | --- | --- |
| **Node.js** (recommended) | In this folder run `npm start` — no `npm install` needed | opens <http://localhost:3000> for you |
| **Python 3** | In this folder run `python -m http.server 3000` | <http://localhost:3000> |
| **VS Code** | *File > Open Folder* → this folder, install the **Live Server** extension, right-click `index.html` → *Open with Live Server* | opens automatically |

`npm start` runs the included zero-dependency [`server.js`](server.js). Options: `node server.js --port 8080`,
`node server.js --host 0.0.0.0` (or the `PORT` / `HOST` environment variables). If a port is busy it tries the
next one, and it prints every file the page asks for that is not part of this copy (`[missing] ...`).

**Serve this folder as the web root.** The site loads its files from `/_next/...`, so it must live at the root of
the URL (`http://localhost:3000/`), not in a sub-folder (`http://localhost:3000/webcopytest/`). With VS Code, open
*this* folder, not a parent folder.

## Why it would not launch

1. **Opened as a file.** Every asset is linked with a root path (`/_next/static/...`) and the Next.js/Turbopack
   runtime has `/_next/` hard-coded. From `file://` those paths point at the root of your drive, so no CSS or
   JavaScript loads (you only see a giant black shape). The site needs an HTTP server.
2. **Broken file names.** The download tool removed `~` from file names (`090n~5-hq8ny..js` was saved as
   `090n5-hq8ny..js`, the same for `turbopack-0cgli9jkf~aex.js` and `03y33.~oe45ex.js`), but the HTML, CSS and JS
   still asked for the original names. The JavaScript runtime returned 404, so even on a server the loading
   screen stayed at "0 %" forever.
3. **Missing 3D chunks.** Two lazily loaded 3D components (`Twenty3D`, `ProjectGallery3D`) were never downloaded.
   Scrolling to them crashed the page with "This page couldn't load".
4. **Fake / mis-named assets.** All four font files were 130-byte text placeholders (`No Content: ...`), and the
   office photo was saved as `_next/image.html` (really a WebP from Next.js' image optimiser, which only exists on
   a Next.js server).

## What was changed

- **File references:** `index.html`, `_next/static/chunks/0_7-834d877pd.css`, `turbopack-0cgli9jkfaex.js` and
  `111qhi7s.jdpu.js` now use the `~`-less file names that exist on disk.
- **3D fallbacks** (`03y33.oe45ex.js`, the Hero): if a 3D chunk is missing, the page uses the site's own built-in
  2D versions (the ones it shows on devices without WebGL) instead of crashing. The 2D gallery hides photos that
  fail to load. If the missing chunks are added later, the 3D versions are used automatically.
- **Images:** next/image is switched to `unoptimized` (in `111qhi7s.jdpu.js`) so it requests plain files instead
  of `/_next/image?url=...`. `_next/image.html` is restored as `images/office-w-team-small.png`, and the two
  `<img>` tags in `index.html` point to it.
- **Fonts:** the real **Roboto Mono** variable font is installed (Google Fonts, SIL Open Font License — see
  `_next/static/media/RobotoMono-OFL.txt`). The fake **TT Firs Neue** placeholders are removed (commercial font,
  see below). Until real files are added, Next.js' built-in metric-matched fallback (Arial) is used.
- **`file://` helper:** a small script at the top of `<head>` in `index.html` shows these launch instructions
  when the page is opened by double-click. Over `http://` it does nothing.
- **Added:** `server.js`, `package.json`, `404.html` (shown for URLs that were not downloaded, e.g. `/about`) and
  this README.
